# Sherlock — Notes for AI Agents

- **The root package is a shared-utility package, not a client.** It holds `AuthorizedFetch` and the address classifiers (`IsValidAddress`, `IsValidUsername`) and nothing else. There is no `sherlock.Client`, no `Config`, and no `sherlock.Option`. Webpage metadata is `metadata.Get`; ActivityStreams loading is the middleware stack. A monolithic `sherlock.Client.Load` used to do both jobs — RSS, Atom, JSON Feed, microformats, icon and link discovery — and a `Client.Metadata` wrapper used to thread fetch policy into the metadata engine. Both are gone. **Don't add a fetch to the root package**; `metadata.newDocument` is the one place a page is fetched and parsed, and `activitypub.Client.Load` is the one place an AS2 document is.

- **The subpackages are stacked client middlewares, and stacking ORDER is important.** `bridgyfed` and `tagspub` rewrite identifiers into WebFinger handles, so they MUST sit *above* `webfinger` in the stack; `webfinger` resolves handles to URLs that `activitypub` then loads; `tombstone` substitutes a placeholder for Gone documents. `activitypub` is the only layer that fetches, and the only one whose `New` takes no inner client. Each subpackage's README states its own placement rule.

- **A `streams.Client.Load` option bag is `...any`, and only `remote.Option` survives the trip.** The stack passes `options ...any` down verbatim and the bottom layer keeps only what `remote.Options(options...)` can type-assert — everything else is discarded with no error anywhere. Emissary once wrapped a bearer token as a `sherlock.Option` and the token silently never reached the wire. **Pass `remote.Option` values to the stack, and a sub-package's own option type (`metadata.GetOption`, `activitypub.ClientOption`) to that sub-package.** Never invent a cross-package option type again.

- **`remote.Options` is variadic, so the spread is important: `remote.Options(options...)`.** `[]any` satisfies `any` — so `remote.Options(options)` compiles, passes the whole slice as a single value, matches no `Option`, and returns an empty set. Every caller option is dropped with no error anywhere: the document still loads, just unmodified. `activitypub.Client.Load` shipped that way and dropped every per-call option reaching the terminal client in the stack, including the `Accept` header `bridgyfed` injects above it. `TestLoad_PerCallRemoteOptionReachesRequest` locks it. Any new middleware that filters the `...any` bag needs the same spread, and the matching rule for forwarding a `Load` down the stack is in Emissary's `tools/AGENTS.md`.

- **Network access is SSRF-hardened by default, inherited from [remote](https://github.com/benpate/remote).** `AllowPrivateIPs` defaults to FALSE, so private/loopback fetches are blocked and response sizes are capped. Self-hosted/LAN targets, and tests against `httptest` servers, must opt in — `metadata.WithAllowPrivateIPs(true)` for the engine, `activitypub.WithAllowPrivateIPs(true)` for the stack. These are independent settings on independent fetches, and WebFinger's `digit.Lookup` is a third, so allowing private IPs in one place and not the others yields a partial allowance and a confusing refusal.

- **`Result(&someMap)` lets `remote` pick a decoder from the Content-Type, and it REFUSES `text/html`.** A perfectly healthy HTML response then comes back as an error from `txn.Send()`, indistinguishable from a failed fetch. Read into a `[]byte` and parse it yourself — `metadata.newDocument` does, with the comment *"Result(&body) bypasses remote's content-type-driven decoding"*. `activitypub.Client.Load` still uses `Result(&map)`; it survives only because it treats any error as "not ActivityPub" and falls through. Separately, `processResponse` errors on **every** non-2xx whatever the `Result()` target is, so reading into bytes does not make a 403 succeed — a multi-step loader must hold the first step's error aside rather than returning it.

- **The metadata engine (the `metadata/` sub-package) never touches hannibal.** `metadata.Get` returns the oEmbed-adjacent `metadata.Preview` built by pure extractors merged in precedence order (AS → OG → Twitter → oEmbed → HTML). The layering is enforced by the package boundary: `metadata` has no hannibal import, and any future AS2 projection belongs in a package that imports `metadata` — never the reverse. Extractors return sparse `partial`s (unexported — the engine's internals are deliberately not API) and NEVER write into a `Preview` — write-if-empty into a shared result is the old defect pattern this engine replaces. Extractors must stay pure over bytes already in hand.

- **A `partial`'s fields are nullable values, and `IsZero()` is a trap.** They are `null.String` / `null.Object[T]` (rosetta), never pointers, so nothing in the package dereferences — a null field reads back as its own zero value, which is why `hasEmbedSignals` can `switch og.Kind.Object()` with no presence test. `merge` must ask `IsPresent()`: `IsZero()` reads TRUE for a *present-but-empty* value and would silently demote a source that did speak. The one deliberate exception is `firstString`, which wants a usable value and so does use `IsZero()`. Groups reach the `Preview` as copies, so the icon backfill can never write back into the partial that won.

- **`Preview` groups are POINTERS and are nil when no source filled them.** `Thumbnail`, `Embed`, `Provider` are filled whole from one source or not at all, so every consumer must nil-check before dereferencing. Scalars (`Title`, `Description`) are plain strings and read back empty instead.

- **Precedence is argument order, plus ONE named exception pick.** `merge()` call order in `metadata.extract` IS the global precedence (AS → OG → Twitter → oEmbed → HTML); the only deviation is the URL pick (AS id → rel=canonical → og:url, same-origin required), which merge never touches. Groups (Thumbnail/Embed/Provider/Authors) fill whole from one source with validity floors — never mix one source's URL with another's dimensions. Changing precedence means editing `metadata.extract`, nothing else.

- **Embed has NO exception pick — don't reintroduce one.** Until 2026-08 `extract()` ended with `result.Embed = firstValidEmbed(oe, tw, og)`, which unconditionally overwrote whatever merge had chosen. That made TWO competing definitions of embed precedence, and the one that looked authoritative (merge order) was inert — reordering the `merge()` calls changed nothing. The override is gone: an `og:video` player now beats an oEmbed player, because OG merges first. The tradeoff is deliberate and important: `og:video` is ambiguous (file vs. player), so `finalizeOpenGraphEmbed` classifies it and `validEmbed` rejects a file posing as an iframe. `TestMetadata_EmbedPrecedence_*` in `get_test.go` locks the rule end to end — five of those tests fail if the override comes back.

- **The oEmbed endpoint call is lazy and must stay that way.** `(result.Embed == nil && hasEmbedSignals(...)) || oembedCouldHelp(result)` gates the only extra network hop (both helpers live in `extract-oembed.go`). The `result.Embed == nil` guard matters: precedence is call order, so an embed already merged from OG or Twitter has won, and fetching oEmbed to improve on it would buy nothing. `oembedCouldHelp` deliberately does NOT test Embed (every preview lacks an embed before oEmbed runs — testing it would make the gate always fire) or Description/Language (the oEmbed spec has neither). It replaced a `fieldSet` bitmask + `Preview.couldImprove` in 2026-08: the mask had one caller and one value, and half its bits were never set — don't reintroduce a capability calculus for a single gated source. Provider embed HTML enters the model only through `oembed.Embed()` classification. Whether non-extractable markup becomes a sandboxed embed is the operator's `AllowSandboxEmbeds` option (default FALSE = no embed) — a uniform UX/product decision, NOT a trust tier keyed on how the endpoint was found. Don't reintroduce registry-vs-discovery provenance: the sandbox plan runs in an opaque-origin iframe and is MORE contained than the plain iframe plan, so gating it on provenance was backwards, and the oembed library deliberately no longer reports provenance.

- **Microformats2 is NOT supported and is not coming back.** Both the document `h-entry` parser and the `h-feed` actor parser are deleted, and mf2 was already dropped from the metadata engine's source list by decision. Adoption is ~0.5% of sites. Don't re-propose it, and don't treat its absence as a gap to fill.

- **AS2 alternate discovery (FEP-22b6) is MISSING, and it is filed.** The old `document-html-jsonld-linked.go` was misnamed — it did `rel=alternate` AS2 discovery, not schema.org JSON-LD — and it went out with the monolithic client. Nothing replaces it, so an HTML page that advertises an AS2 alternate is not followed to it. Don't rebuild it ad hoc; the bug spec names where it belongs.

- **Identifier classification is strict and lives in [uri](https://github.com/benpate/uri).** Whether a value "looks like" a URL or an `@handle` is decided by `uri` validation (real IANA TLDs, 2+ segments), which `IsValidAddress` builds on. When a test for that classification fails after a `uri` upgrade, the test assumption is usually what drifted — not the code. A related trap, already fixed: `bridgyfed.TestLooksLikeBluesky` asserted that `not-enough-segments.net` was invalid. It has two segments and a real TLD, so the stricter `uri.ValidateHostname` correctly accepts it — the test encoded an obsolete assumption, and the function was right. Fix a case like that in the test, not the function.

- **Untrusted-input parsers are fuzzed; keep new ones that way.** The extraction parsers have `Fuzz*` coverage in `metadata/fuzz_test.go`, and the identifier classifiers in the root `fuzz_test.go`. Regexes are static patterns (`regexp.MustCompile`) — no untrusted input is ever compiled into a regex. A new parser of remote bytes should arrive with its own fuzz target.

- **`meta/` holds the README banner image and no Go code.** It is not a package; don't look for one there.
